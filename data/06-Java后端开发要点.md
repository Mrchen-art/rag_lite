# Java 后端开发要点

## 语言基础

String 是不可变的，底层在 Java 九之后使用字节数组加编码标记存储，频繁拼接应改用 StringBuilder。equals 和 hashCode 必须同时重写，且要用相同的字段集合计算，否则放入哈希容器后会出现查找不到的情况。接口与抽象类的区别在于接口强调能力契约并支持多实现，抽象类强调代码复用和模板方法。

## 集合框架

ArrayList 基于动态数组，默认初始容量十，扩容为原容量的一点五倍，支持随机访问。LinkedList 基于双向链表，适合频繁在中间插入删除。HashMap 在 Java 八之后引入红黑树，当链表长度超过八且数组容量不小于六十四时树化，退化阈值为六。ConcurrentHashMap 在 Java 八之后使用数组加链表加红黑树配合 CAS 和分段锁实现高并发。

## 并发编程

线程的创建方式包括继承 Thread、实现 Runnable 和通过线程池提交。线程池的核心参数有核心线程数、最大线程数、空闲存活时间、工作队列和拒绝策略，不建议使用 Executors 的快捷方法创建，因为无界队列可能导致内存溢出。synchronized 是可重入的悲观锁，Java 六之后引入了偏向锁、轻量级锁等优化。volatile 保证可见性和禁止指令重排序，但不保证原子性。AQS 是 ReentrantLock、CountDownLatch 等同步工具的底层框架。

## JVM

内存区域分为方法区、堆、虚拟机栈、本地方法栈和程序计数器，其中堆和方法区线程共享。垃圾回收判断对象存活使用可达性分析而不是引用计数。常见的垃圾收集器有 Serial、Parallel、CMS 和 G1，服务端默认使用 G1。类加载采用双亲委派模型，保证核心类库不被篡改。排查线上问题常用 jstack 看线程栈、jmap 导出堆快照、jstat 观察垃圾回收情况。

## Spring 生态

控制反转把对象的创建和依赖管理交给容器，依赖注入是实现方式。面向切面编程通过动态代理实现日志、事务、权限等横切关注点，JDK 动态代理要求目标类实现接口，CGLIB 通过生成子类代理。Spring Boot 的自动配置基于条件装配和 SPI 机制。事务失效的常见原因包括方法非 public、自调用没有经过代理、异常被捕获且未抛出、以及数据库引擎不支持事务。

## MySQL 与 Redis

事务的四大特性是原子性、一致性、隔离性和持久性。隔离级别从低到高依次为读未提交、读已提交、可重复读和串行化，MySQL 默认可重复读并通过间隙锁配合 MVCC 解决大部分幻读问题。索引底层是 B+ 树，联合索引遵循最左前缀原则，回表可以通过覆盖索引避免，慢查询排查用 explain 分析执行计划。Redis 常用于缓存、分布式锁和排行榜，缓存三大问题是穿透、击穿和雪崩，分别用空值缓存加布隆过滤器、互斥锁加逻辑过期、随机过期时间来应对。
