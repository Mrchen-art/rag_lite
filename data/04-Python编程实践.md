# Python 编程实践

## 数据结构与惯用法

列表是动态数组，尾部追加是均摊常数时间，但头部插入需要移动所有元素，复杂度为线性。需要频繁在两端操作时应该用双端队列 deque。字典基于哈希表实现，查找和插入平均为常数时间，Python 三点七之后保持插入顺序。集合适合去重和成员判断。判断键是否存在应使用 in 而不是依赖异常捕获。

## 生成器与迭代器

生成器用 yield 逐个产出值，只在被需要时计算，因此可以处理远大于内存的数据流，也是惰性求值的基础。生成器表达式写法简洁，适合简单变换。itertools 模块提供了无限计数器、排列组合、分组等高效工具。使用生成器时要注意它是一次性的，遍历结束后需要重新创建。

## 装饰器与上下文管理器

装饰器本质上是一个接收函数并返回函数的高阶函数，常用于日志、计时、权限校验和缓存。用 functools 的 wraps 保留原函数的元信息是必须养成的习惯。上下文管理器通过 enter 和 exit 协议管理资源的获取与释放，用 contextmanager 装饰器可以把一个生成器函数快速变成上下文管理器，比手写类更简洁。

## 并发模型

Python 的全局解释器锁保证同一时刻只有一个线程执行字节码，因此多线程适合 I/O 密集型任务而不适合 CPU 密集型任务。CPU 密集型任务应使用多进程绕开锁的限制。异步IO通过事件循环在单线程内切换协程，适合高并发网络请求， asyncio 配合 aiohttp 可以在单机上支撑大量并发连接。选择并发模型时先判断瓶颈在 I/O 还是 CPU。

## 常见陷阱

默认参数不要用可变对象，否则多次调用会共享同一份数据，正确写法是用 None 作为哨兵值。遍历列表的同时增删元素会导致跳过元素，应遍历副本或用列表推导式重建。判断空值应利用对象的布尔性而不是与 None 比较。字符串拼接在循环中要用 join 而不是加号，后者会不断创建新对象。

## 工程化

虚拟环境用于隔离项目依赖，避免版本冲突。项目依赖应导出为 requirements 文件，生产环境必须锁定版本号。代码风格遵循 PEP 8，用类型注解提升可读性和静态检查能力。日志要用标准库 logging 模块而不是 print，方便分级和输出到文件。单元测试用 unittest 或 pytest，核心逻辑必须有测试覆盖。性能分析用 cProfile 定位热点，不要凭直觉优化。
