# 操作系统与计算机网络

## 进程与线程

进程是资源分配的基本单位，拥有独立的地址空间；线程是 CPU 调度的基本单位，同一进程内的线程共享地址空间。线程切换只需保存和恢复少量寄存器与栈，开销远小于进程切换。多线程共享数据时需要同步，否则会出现竞态条件。多进程通信方式包括管道、消息队列、共享内存和信号，其中共享内存最快但需要额外的同步机制。

## 死锁

死锁产生的四个必要条件是互斥、占有且等待、不可抢占和循环等待，四个条件同时成立才会发生死锁。预防死锁的方法包括一次性申请所有资源、按固定顺序申请资源、以及允许资源被抢占。避免死锁的代表算法是银行家算法，在分配前判断系统是否仍处于安全状态。检测与恢复则允许死锁发生，通过资源分配图检测后回滚或终止进程。

## 内存管理

虚拟内存让每个进程拥有独立的连续地址空间，通过页表映射到物理内存。分页机制把内存划分为固定大小的页，地址转换由内存管理单元完成，快表用于加速转换。缺页中断发生在访问的页面不在内存时，需要从磁盘调入。页面置换算法有先进先出、最近最少使用 LRU 和时钟算法，LRU 效果最好但实现代价高，时钟算法是工程上的折中。

## TCP 三次握手与四次挥手

建立连接需要三次握手：客户端发送同步报文，服务端回复同步加确认，客户端再确认。三次握手的意义在于双方都确认对方的发送和接收能力正常，并同步初始序列号；两次握手无法防止已失效的连接请求突然到达服务端而建立错误连接。断开连接需要四次挥手，因为 TCP 是全双工的，每个方向都要单独关闭。主动关闭方进入超时等待状态，确保最后的确认报文能够到达。

## 可靠传输与拥塞控制

TCP 通过序列号、确认应答、超时重传和滑动窗口实现可靠传输与流量控制。拥塞控制的目标是避免把过多数据注入网络，算法包括慢启动、拥塞避免、快速重传和快速恢复。接收方窗口和拥塞窗口共同决定发送方的实际发送量。UDP 不保证可靠和有序，但头部开销小、无连接建立延迟，适合音视频和实时游戏。

## HTTP 与 HTTPS

HTTP 是无状态的应用层协议，常见状态码中 200 表示成功，301 和 302 表示重定向，400 表示请求错误，401 表示未认证，403 表示无权限，404 表示资源不存在，500 表示服务端错误。从 1.1 开始支持长连接，2.0 引入多路复用和头部压缩，3.0 基于 UDP 的 QUIC 协议。HTTPS 在 HTTP 与 TCP 之间加入安全层，通过非对称加密协商密钥、对称加密传输数据，并用证书验证服务端身份。
